# Configuration

The embedded API takes a validated `StorageConfig` directly. YAML is a server startup concern. The server takes the config file path from its first argument or uses `config/application.yaml` relative to the working directory. The build includes that file as runtime data. Port `50001` is a Java constant. There is no application setting for port, queue capacity or recovery mode. [Application](../server/src/main/java/com/ryszardzmija/shaledb/server/Application.java) · [Server build](../server/BUILD.bazel) · [Example configuration](../config/application.yaml)

## Loading and mapping

1. `ApplicationConfigLoader.fromYAML` enables failure on unknown properties and disables float-to-int conversion and scalar coercion in its Jackson YAML mapper. `loadFromFile` rejects null paths, missing files, directories/nonregular files, unreadable files and zero-byte files. It then reads the file into `ApplicationConfigDto` containing a `StorageConfigDto`. Malformed syntax, incompatible structure/types, and file-read errors become `ConfigLoadingException` with distinct messages. The preliminary size check only detects a literally empty file. A YAML root that binds to null is returned without a DTO check, and `Application` then dereferences it before storage mapping. [ApplicationConfigLoader](../server/src/main/java/com/ryszardzmija/shaledb/server/config/ApplicationConfigLoader.java) · [ApplicationConfigDto](../server/src/main/java/com/ryszardzmija/shaledb/server/config/ApplicationConfigDto.java)
2. DTO numbers are nullable boxed `Long`s so missing and zero can be distinguished. `StorageConfigMapper.toStorageConfig` requires the storage section and each field, converts the path with `Path.of` and constructs `StorageConfig`. Missing fields produce a field-specific `StorageConfigException`. The mapper wraps `IllegalArgumentException` from invalid path syntax or record validation. Direct construction of the record exposes its own `IllegalArgumentException`. There are no per-field fallback values. [StorageConfigDto](../storage/src/main/java/com/ryszardzmija/shaledb/storage/config/StorageConfigDto.java) · [StorageConfigMapper](../storage/src/main/java/com/ryszardzmija/shaledb/storage/config/StorageConfigMapper.java) · [StorageConfig](../storage/src/main/java/com/ryszardzmija/shaledb/storage/config/StorageConfig.java)
3. Parsing and mapping finish **before** the server's main resource-management `try` block. The server creates the directory afterward. Opening the engine derives `SegmentConfig` and `DurabilityConfig` and fixes them for the lifetime of that instance. File edits affect a subsequent startup. [Application](../server/src/main/java/com/ryszardzmija/shaledb/server/Application.java) · [SegmentConfig](../storage/src/main/java/com/ryszardzmija/shaledb/storage/hash/segment/model/SegmentConfig.java) · [DurabilityConfig](../storage/src/main/java/com/ryszardzmija/shaledb/storage/durability/DurabilityConfig.java)

## Storage fields

All four fields below are required. The values shown come from the checked-in example. Byte units are literal counts, so 65,536 bytes is 64 KiB. [Example configuration](../config/application.yaml)

| YAML field | Type, example and validation | Consumer and effect on existing files |
| --- | --- | --- |
| `storage.maxSegmentSize` | Signed `long` bytes, `65536`. Must accommodate `13 + maxPayloadSize` bytes. | `SizeBasedRolloverPolicy` compares actual file size after a mutation. `SegmentReader` rejects a present start offset `>=` this same setting. Lowering it can leave old records indexed but unreadable. Increasing it can admit those offsets and defer future rollover. Startup does not split old files or pre-roll a full active file. |
| `storage.maxPayloadSize` | Signed `long` bytes, `16384`. Must be in `[1, Integer.MAX_VALUE - 13]`. Measures combined key and value bytes, excluding the header. | `HashIndexEngine` and `RecordWriter` enforce this budget before append. `RecordReader` uses it on every present lookup and in every `IndexBuilder` scan. A decrease below any historical payload can block the entire open, even for an overwritten or deleted key. A compatible increase can restore readability and also raises the allocation budget. |
| `storage.segmentDir` | YAML string, `data/segments`, converted to non-null `Path`. Mapper requires presence and platform-valid path syntax. There is no blank, absolute-path or exclusive-ownership check. | `Application` creates it if necessary. The factory and discoverer expect a directory. A relative path resolves against the process working directory, independently of the YAML file's location. Changing it opens the files at the new location. No data is migrated. Pointing at an empty directory initializes a new store. |
| `storage.durabilityMode` | Non-null `DurabilityMode` enum. The sole declared name is `SYNC_EACH_WRITE`, also the example. Tests reject the lower-case spelling. The current loader also accepts numeric ordinal `0`, confirmed with the checked-in mapper settings. | `SegmentWriter` forces the active file after each record and before publication. There is no second supported policy to switch to. No bytes in a record describe the mode that wrote it. Directory creation force and final close force occur separately. |

Sources for these runtime uses are [SizeBasedRolloverPolicy](../storage/src/main/java/com/ryszardzmija/shaledb/storage/hash/segment/rollover/SizeBasedRolloverPolicy.java), [SegmentReader](../storage/src/main/java/com/ryszardzmija/shaledb/storage/hash/segment/model/SegmentReader.java), [RecordReader](../storage/src/main/java/com/ryszardzmija/shaledb/storage/serialization/io/RecordReader.java), [SegmentWriter](../storage/src/main/java/com/ryszardzmija/shaledb/storage/hash/segment/model/SegmentWriter.java) and [DurabilityMode](../storage/src/main/java/com/ryszardzmija/shaledb/storage/durability/DurabilityMode.java).

## Compatibility consequences

`StorageConfig` uses `FormatInfo` to check the largest encoded record up front. It checks the payload range before adding the header, and accepts equality at the segment threshold. This ensures each new record fits within an empty segment's size budget. A record appended to a partly used segment can still cross the threshold because rollover runs after append. Buffer allocation remains subject to available heap. [Record format](record-format.md) · [Segment management](segment-management.md)

Reopening with `maxSegmentSize = 32768` and `maxPayloadSize = 16384` can rebuild an older record's index entry at offset 40,000 if every record meets the payload limit. A lookup that reaches that entry then throws `IllegalStateException` under the existing offset check. A lower payload budget can fail earlier during construction, even when all historical records are structurally valid. This path uses the existing `DataCorruptionException` and identifies the declared payload and configured limit in the message. Replay aborts without skipping or discarding those records. [IndexBuilder](../storage/src/main/java/com/ryszardzmija/shaledb/storage/hash/index/IndexBuilder.java) · [SegmentReader](../storage/src/main/java/com/ryszardzmija/shaledb/storage/hash/segment/model/SegmentReader.java) · [RecordReader](../storage/src/main/java/com/ryszardzmija/shaledb/storage/serialization/io/RecordReader.java)

Separating write admission from the historical read budget would require a bounded allocation policy and an explicit compatibility outcome. A persistent statement of format capabilities could distinguish an incompatible open from damaged bytes and would add metadata requiring durable publication.
